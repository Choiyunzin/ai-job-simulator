## 2. 업무 프로파일 (입력 문항)

| 코드 | 화면 | 문항 | 쓰이는 곳 |
|---|---|---|---|
| Q.A | 직무 | 소속 부서명, 팀 인원(구간), 직군→직종→직렬→직무(사내 목록), 직책자 여부→팀장/실장, 직급, Pay Grade, 근속기간(구간), 현 직무 경력(구간) | 리포트 표시, 결과 제출, 리더 역할 노출 |
| Q.R | 나의 역할 | 직무 역할(+직책자는 리더 역할) 5점 척도, 역할 직접 추가 | 업무 고르기 후보, 강점·보완 역할 |
| Q.B-1 | 업무 고르기 | 표준 업무·나의 역할·예시 업무를 세로 체크 목록으로 선택, 직접 추가 (**개수 제한 없음**) | 이후 모든 분석의 단위 |
| Q.B-2 | 업무 구체화 | 업무마다 비율(0~100, 25 단위 눈금+숫자 입력), 빈도, 업무 유형, 가장 어려운 점, 주요 활동(8가지), 사용 스킬(최대 3개), 중요도. '비율 유지하며 합계 100%로 맞추기' 버튼 | 시간 환산, 업무패턴, 스킬 방향 |
| Q.S | 스킬 수준 | 스킬별 5단계: 1 개념인지 · 2 가이드수행 · 3 독립수행 · 4 복잡대응 · 5 전문가 (업무에 연결한 스킬이 먼저) | 스킬 방향 사분면, AI 준비도, 인사이트 |
| Q.C | AI 활용 수준 | 업무별 0~4단계, 1단계 이상이면 활용 방식(맡기기·피드백 반복·함께 다듬기·배우기·검토받기) | 이미 실현한 효과, AI 업무 유형 |
| Q.D | AI 적용 가능성 | 업무별 높음·보통·낮음·모름 (표준 업무는 연구 기준 추천 표시) | AI 적용 가능성(잠재력) |
| Q.H | AI 활용 환경 | 사용 가능한 AI 도구, 팀의 AI 활용 방식, 주당 AI 학습 가능 시간 | 사내 실현 가능성, 시뮬레이션 보정 |

삭제한 문항: 성공 기준·걱정(Q.E·F), 승인·자료(Q.G), 나의 이야기, 응답 반영도.
(승인 방식은 '팀장 1단계', 개인정보는 '일부 있어요'를 기본값으로 계산)

### 스킬 단계 예시 (교육체계 설계)

| 단계 | 기준 |
|---|---|
| 1 개념인지 | 교육·역량 분야 입문 단계, 기본 원리·구조를 학습 중 |
| 2 가이드수행 | 팀 지원을 받아 개발 체계 설계 초안을 수립 |
| 3 독립수행 | 본인 책임 하에 개발 체계 설계를 결정·실행 |
| 4 복잡대응 | 복잡·변동 상황에서도 개발 체계 설계를 정밀 조정·재구성 |
| 5 전문가 | 교육·역량 분야의 신규 프레임·표준을 정립할 수 있음 |

## 3. 해석법 팝업

> 이 결과는 정답이나 평가가 아닙니다. 내 일을 데이터로 비춰 보며 지금 하는 일의 의미를 되짚고, 다음에 해 볼 일을 찾는 **출발점**입니다. 아래 세 가지 시선으로 읽어 보세요.

1. **사실로 읽기**: 숫자와 그래프는 내가 응답한 그대로의 모습입니다. 좋고 나쁨을 판단하기 전에 "내 일이 실제로 이렇게 구성되어 있구나"를 먼저 확인해 보세요.
2. **의미로 읽기**: 왜 이런 결과가 나왔는지 생각해 보세요. 내 역할, 팀의 상황, 지금 시기의 업무를 떠올리면 같은 숫자도 다른 의미를 가집니다.
3. **가능성으로 읽기**: 결과를 바탕으로 무엇을 바꿔 볼 수 있을지 찾아보세요. 스킬 보강, 업무 조정, AI와 함께 일하기 중 바로 시작할 수 있는 작은 행동 하나면 충분합니다.

## 4. 업무현황·AI 영향진단 리포트 (7개 모듈 · 한 페이지 + 책갈피)

리포트 첫 줄은 데이터 요약 문장이다. 책갈피는 ① 업무현황 / ② AI 영향진단 두 묶음으로 나뉜다.

| 영역 | 모듈 | 내용 |
|---|---|---|
| ① 업무현황 | 01 직무현황 | 소속·팀 인원·직무·직책·근속·직무경력, 업무 수, 가장 많이 하는 활동, 스킬 수준 평균, 태스크별·활동별 비중 |
| | 02 태스크 & 스킬 | 업무별 주요 활동·연결 스킬·내 수준 표, 스킬별 5단계 막대 |

## 5. 스킬 방향 분석 (AI 적용 ↔ 스킬 연결)

- **가로축**: 업무의 AI 적용 가능성 (시뮬레이션 잠재력과 같은 값)
  - 직접 입력 업무: 업무 유형별 자동화 상한 × 적용 가능성 배수 (높음 1.15 · 보통 0.85 · 낮음 0.45 · 모름 0.8)
  - 표준 업무: 업무 유형별 자동화 상한 × 연구 등급 계수 (E1 1.0 · E2 0.8 · E0 0.2)
- **세로축**: 그 업무에 연결한 스킬의 내 수준 평균 (1~5)
- **원 크기**: 시간 비중
- **기준선**: AI 적용 가능성 40%(초기 가정, `src/workmap.ts`의 `AI_MID`), 스킬 3점(독립수행)

| AI 적용 가능성 | 내 스킬 | 영역 | 스킬 방향 |
|---|---|---|---|
| 높음 | 높음 | **AI에 맡기고 검증하는 업무** | 직접 하던 일 → AI 결과를 설계·검증하는 역할로 이동 |
| 높음 | 낮음 | **AI로 배우며 하는 업무** | AI를 코치처럼 쓰되, 결과를 판단할 기본 스킬은 함께 보강 |
| 낮음 | 높음 | **사람 고유의 강점 업무** | AI로 아낀 시간을 여기에 재투자 |
| 낮음 | 낮음 | **사람이 직접 키워야 할 업무** | 교육·코칭으로 육성 우선 |

**AI 준비도**: 이름에 'AI'가 들어간 스킬(예: AI 도구 활용)의 수준과 AI 적용 가능 업무 수를 함께 본다. 적용 가능 업무가 있는데 이 스킬이 2단계 이하이면 "지금은 실제로 맡기기 어려움"으로 표시한다.

## 6. 생산성 시뮬레이터 (③)

화면 순서는 결론부터 보여 준다.

1. **재설계 가능 범위**: 연구 기반 노출도 / 사내 실현 가능 / 현재 활용도 세 막대, 재설계 시 예상 생산성(절감 시간·절감률), 재설계 가능 업무(절감 5% 이상) 수와 시간 비중
2. **요약**: 지금 방식 → AI만 적용 → 업무 흐름까지 재설계 (투입 시간·절감률·대기 시간), 품질·오류 위험 점수 (이 업무 / 전체 업무, 주당 / 건당 전환)
3. **시간은 어디서 줄고 어디서 늘었나**: '사람이 하던 일 / AI 때문에 새로 생긴 일 / 대기(빗금)' 세 묶음, 세부 9개 항목 표
4. **업무 흐름 재설계 항목**: 검증 체크리스트 표준화, 위험도별 승인 차등화, 프롬프트·템플릿 라이브러리, 요청 기준·셀프서비스 (④의 상황 대응 선택도 반영)
5. **업무 흐름으로 보기**, **시간 구성 직접 조정**(막대 또는 숫자)

### 핵심 계산

| 항목 | 공식 |
|---|---|
| 주당 시간 | 기준 근무시간(기본 40) × 업무 비율 |
| 대체율 r | 잠재력 × (1 − 현재 활용 단계에서 이미 실현한 비율), 상한 80% |
| AI 입력·지시 | 대체된 직접작업 × 단계별 지시 비율 |
| AI 결과 검토 | 대체된 직접작업 × 유형별 검토 비율 |
| 오류 재작업 | 대체된 직접작업 × 단계별 오류율 × 수정비용 0.5 |
| 도구 유지관리 | 단계별 주당 시간 × min(1, r ÷ 0.3) |
| 승인 대기(경과시간) | 기존 대기 × (1 + 0.5 × r) — 투입 시간 합계에서 제외 |
| 요청 증가 | r × 0.3 — 절감률과 분리해 '늘어난 요청 처리'로 표시 |
| 절감률 | (기존 − 변경 후) ÷ 기존 × 100 |

## 7. 실행 인사이트 (④)

| 구획 | 내용 |
|---|---|
| ④-1 AI 활용 가능 영역과 업무 혁신 방향 | 진단에서 뽑은 다음 행동 최대 5개(아래 순서) + 먼저 실험해 볼 업무(누르면 ③으로 이동) |
| ④-2 AI 활용 시 주의할 점 | 병목이 생기는 업무 TOP2, AI 활용 범위 정하기(연구 최전선 업무, 사내 실현이 어려운 업무, 주의 문구) |
| ④-3 활용 상황 미리 겪어 보기 | AI를 쓰기 시작하면 생기는 상황(요청 증가, 품질 함정 등)에 대응을 골라 보고, 고른 대응이 전체 업무 시간에 반영되는 결과를 확인 |
| ④-4 아낀 시간, 어디에 쓸까? | 주당 근무시간 바꿔 보기, 절감 시간의 행방, 확보한 시간 재투자(사분면 기반 추천), 최종 리포트·인쇄/PDF·JSON·CSV, 결과 제출 |

인사이트 생성 순서:

1. **AI 준비도**: AI 도구 활용 스킬 ≤ 2단계이고 AI 적용 가능 업무가 있을 때, 다음 단계 기준 제시
2. **맡기기**: 'AI에 맡기고 검증' 업무 (없으면 '먼저 실험해 볼 업무')
3. **함께 배우기**: 'AI로 배우며' 업무와 가장 낮은 연결 스킬
4. **시간 재투자**: '사람 고유 강점' 업무
5. **육성 우선**: '직접 키울' 업무
6. (빈자리가 있으면) 먼저 실험해 볼 업무, 스킬 미연결 업무 안내

## 8. 결과 제출

제출 방식(Power Automate → SharePoint, 스키마 v2)은 현재 구조 그대로 두고 추후 결정한다. 팀 단위 진단은 제출 데이터 집계로 만든다.

---

## 9. 관리자 설정 (HTML 맨 위 칸)

| 칸 | 형식 | 비어 있으면 |
|---|---|---|
| 직무 목록 | 직군 · 직종 · 직렬 · 직무 (탭 구분 4칸) | 기본 직무 목록 |
| 역할 목록 | 직무 · 역할 (탭 구분, 직무 칸 '리더' = 리더 역할) | 교육기획 기본 역할 5개, 리더 역할 6개 |
| 표준 Task 목록 | 13칸 (직무, Task ID, Task 문장, 업무 유형, … , 노출 등급, 기준일) | 모든 업무를 유형 추정으로 계산 |
| 스킬 목록 | 직무 · 스킬명 · 스킬 정의 · 1~5단계 설명 (탭 구분 8칸, 직무 '공통' = 모든 직무) | 기본 예시 스킬 (AI 도구 활용·데이터 분석·문서·보고·소통·협업 + 교육 직무 3개) |
| 결과 제출 설정 | SUBMIT_URL, SUBMIT_KEY | 제출 카드 숨김 |

사내용 파일 만들기:

```bash
node scripts/build-single.mjs --list 목록.tsv --roles 역할.tsv --tasks 표준Task.tsv --skills 스킬.tsv --out ai-job-simulator-사내.html
```

## 10. 남은 결정 사항

- **결과 제출·팀 단위 집계**: 제출 항목과 집계 방식
- **AI 적용 가능성 기준선(40%)**: 응답 데이터가 쌓이면 전사 중앙값으로 교체
- **AI 활용 환경(Q.H)**: 화면을 유지할지, 회사 기준 도구로 고정하고 뺄지
- **스킬 수준(Q.S)**: 모든 스킬을 물을지, 업무에 연결한 스킬만 물을지
- **사내 스킬셋 반영**: 스킬 목록 칸에 사내 스킬과 단계 정의 입력 (AI 도구 활용 스킬은 이름에 'AI' 포함)
