# AI와 함께라면, 내 일은 어떻게 달라질까? — AI와 함께 일하기 시뮬레이터

사내 AI 학습 소모임용 인터랙티브 웹게임입니다. 참가자가 자기 업무를 직접 정의하고, AI 도입 전후의 시간·품질·위험 변화와 AI와 일할 때 생기는 상황을 체험한 뒤, 업무를 재설계합니다.
백엔드, API 키, 외부 AI 호출 없이 브라우저에서만 동작합니다.

## 1-1. 사내 직무 목록 쓰기 (직군 → 직종 → 직렬 → 직무)

HTML 파일 **맨 위**에 '직무 목록' 칸이 있습니다. 메모장으로 열어 이 칸에 `직군 직종 직렬 직무`를 한 줄씩(탭 구분) 넣고 저장하면, 직무 질문이 4단 선택으로 바뀝니다. 엑셀에서 네 칸을 복사해 붙여넣으면 됩니다.

사내용 파일을 한 번에 만들려면:

```bash
node scripts/build-single.mjs --list 목록.tsv --out ai-job-simulator-사내.html
```

**사내 목록이 들어간 파일과 목록 파일은 이 저장소에 올리지 마세요.** (`*.tsv`, `*-사내.html`은 `.gitignore`에 들어 있습니다.)
목록 칸이 비어 있으면 기본 직무 목록으로 동작합니다.

**역할 진단(Q.R)**: 직무 목록 아래 '역할 목록' 칸에 `직무<탭>역할`을 한 줄씩 넣으면, 고른 직무(없으면 직렬)의 역할을 5점 척도로 체크합니다. 직무 칸을 `리더`로 적으면 팀장·실장용 리더 역할을 바꿀 수 있습니다. 비어 있으면 교육 직무는 기본 교육기획 역할 5개, 팀장·실장은 기본 리더 역할 6개를 씁니다. 체크한 역할은 Q.B에서 업무로 불러올 수 있고, 리포트에 강점(4~5점)·보완 필요(1~2점)로 정리됩니다.
**표준 Task·글로벌 연구 기준 진단(v2)**: HTML 맨 위 세 번째 칸 '표준 Task 목록'에 직무별 표준 업무를 탭 구분 13칸(직무, Task ID, Task 문장, 업무 유형, McKinsey 활동 유형, O*NET 직업 코드, O*NET Task/DWA, 대응 수준, 노출 등급 E0/E1/E2, 채점 근거, 채점 방식, Anthropic 자동화형 비중, 기준일)으로 넣으면, Q.B에서 표준 업무를 고를 수 있고 STEP 3에 연구 기준 진단 카드(노출도·사내 실현 가능·활용도·역량 갭·인프라 갭·4분면)가 나옵니다. 양식은 `templates/표준Task_예시_교육기획.tsv`(예시, 채점 검토 전). 연구 근거값·초기 가정값은 `src/engine/config.ts` 하단(v2)에서 관리합니다.

사내용 파일 만들기: `node scripts/build-single.mjs --list 목록.tsv --roles 역할.tsv --tasks 표준Task.tsv --out ai-job-simulator-사내.html`

사내용 파일 만들기(스킬 목록 포함): `node scripts/build-single.mjs --list 목록.tsv --roles 역할.tsv --tasks 표준Task.tsv --skills 스킬.tsv --out ai-job-simulator-사내.html`

**결과 제출(SharePoint 엑셀 자동 적재)**: HTML 맨 위 '결과 제출 설정' 칸에 Power Automate 'HTTP 요청을 받은 경우' 흐름 주소(`SUBMIT_URL`)와 키(`SUBMIT_KEY`)를 넣으면 STEP 5에 '결과 제출하기' 카드가 나타나고, 동의 후 결과(이름·사번 없음, 근속기간·직무경력은 구간, 소속 부서·팀 인원·업무패턴·스킬 수준 포함)가 흐름으로 전송됩니다. 전송 형식이 바뀌어 `schemaVersion`이 2가 됐으니 흐름의 '스키마' 샘플을 다시 생성해 주세요. 주소가 비어 있으면 카드가 보이지 않습니다. 전송 형식은 `src/submit.ts`, 빌드 옵션은 `--submit-url`·`--submit-key`.
고른 직무 경로에 '교육'이 들어가면 교육 직무용 예시 업무와 재투자 항목이 나옵니다.

## 4. 핵심 계산 로직 (`engine/simulate.ts`)

업무는 **전체 업무 중 비율(%)**로 입력하고, 주당 시간은 `h = 기준 근무시간 × 비율`로 환산합니다(합계는 100% 이하, 나머지는 회의·기타).
처음에는 주 40시간 근무로 환산하고, 마지막 **STEP 5 '④ 실행 인사이트'에서 "주당 근무시간이 ○○시간이라면?"을 직접 바꿔** 볼 수 있습니다(빠른 선택 40·52시간, 30~68시간 조절). 근무시간을 바꾸면 모든 수치가 다시 계산되고, 40시간·52시간일 때의 절감 시간을 나란히 비교해 보여줍니다.
도구 유지관리·재설계 준비 같은 고정 시간이 있어 52시간 값이 40시간 값의 정확히 1.3배가 되지는 않습니다. 빠른 선택 값은 `config.ts`의 `HOUR_BASES`에서 바꿀 수 있습니다.

업무 하나의 주당 시간 `h`를 기준으로 계산합니다. 모든 값은 **주당 시간**이며, 화면에서 '건당'을 고르면 주당 발생 건수로 나눠 보여줍니다.

**AI 도입 전**

- 직접 작업 = h × (1 − 유형별 검토 비중)
- 검토·수정 = h × 유형별 검토 비중
- 승인·대기 = 노동시간 × 유형별 대기 비율 → **경과시간이라 노동시간 합계에서 제외**

**AI 적용 잠재력과 대체율**

- 잠재력 = 유형별 자동화 상한 × 적용 가능성 배수(높음 1.15 / 보통 0.85 / 낮음 0.45 / 모름 0.8)
- 대체율 r = 잠재력 × (1 − 현재 활용 단계에서 이미 실현한 비율), 상한 80%

**AI 도입 후 (같은 업무량 기준)**

| 항목 | 공식 |
|---|---|
| AI 입력·지시 | 대체된 직접작업 × 단계별 지시 비율 |
| 남은 직접 작업 | 직접 작업 − 대체된 직접작업 |
| 기존 검토 | 그대로 유지 |
| AI 결과 검토 | 대체된 직접작업 × 유형별 검토 비율 (+0.1, '검증이 어렵다' 선택 시) |
| 오류 재작업 | 대체된 직접작업 × 단계별 오류율 × 수정비용 0.5 |
| 도구 유지관리 | 단계별 주당 시간 × min(1, r ÷ 0.3) |
| AI 생성(경과) | 주당 건수 × 3분 |
| 승인·대기(경과) | 기존 대기 × (1 + 0.5 × r) |

**업무량 변화는 분리해서 계산합니다.**

- 요청 증가율 = r × 0.3
- 추가 노동 = (유지관리 제외 노동시간) × 요청 증가율

추가 노동은 절감률에 섞지 않고 '늘어난 요청 처리'로 따로 표시합니다.

**절감률** = (기존 총 작업시간 − 변경 후 총 작업시간) ÷ 기존 총 작업시간 × 100

변경 후 총 작업시간에는 재설계 준비 시간(체크리스트·템플릿 제작의 주당 환산)이 포함됩니다.

**재투자할 수 있는 시간** = 기존 − (변경 후 + 늘어난 요청 처리 + 재설계 준비)

**품질·위험은 시간과 별도 지표입니다.**

- 남은 오류율 = (사람 오류 4% × (1 − r) + AI 오류율 × r) × (1 − 검토 적발률 0.7) × 레버
- 위험 점수 = 남은 오류율 × 1200 × 중요도 배수
- 품질 점수 = 70 + 15 × r − 120 × (남은 오류율 증가분) + 레버 가감

**일하는 환경(Q.G·Q.H)**: 모든 업무에 공통으로 곱합니다. 반영 값은 시뮬레이션 화면의 '계산 근거 보기'에 표시됩니다.

- 승인 방식: 승인 대기 ×0.4 / ×1 / ×1.6, 승인자 부담 ×0.3 / ×1 / ×1.4
- 개인정보 포함: 위험 ×0.9 / ×1 / ×1.25 (외부 AI 사용 + 개인정보 많음이면 ×1.1 추가)
- 팀 활용: 유지관리 ×1 / ×0.85 / ×0.7, AI 지시 ×1 / ×0.9 / ×0.8
- 학습 시간: AI 오류율 ×1.1 / ×1 / ×0.85, 유지관리 ×1.1 / ×1 / ×0.9
- 쓸 수 있는 도구가 없으면 유지관리 ×1.3, 자동화 도구가 있으면 반복 처리 업무 잠재력 ×1.1
- Q.I 자유 의견은 계산에 쓰지 않고 최종 리포트와 내보내기에만 담깁니다.

**재설계 레버**: 'AI 적용 후' 값에 재설계 토글과 상황 선택의 레버를 적용합니다. `*Mult` 레버는 곱하고, `*Add` 레버는 더합니다. 각 선택이 어떤 레버를 바꾸는지는 `config.ts`의 `REDESIGN`과 `EVENTS`에 명시돼 있습니다. 무작위 수치는 쓰지 않습니다.

**유형 판정**: 네 유형 점수를 계산해 가장 높은 유형을 고릅니다. 공식은 진단 화면의 '유형 판정 근거 보기'에 표시됩니다.

**상황 카드 추천**: 우려사항(Q.F)에 +3, 성공 기준(Q.E)에 +1.5를 줍니다. 여기에 관련 업무 비중 × 4와 관련 '어려운 점' 건수를 더해 순위를 매깁니다. 일하는 환경도 반영합니다(승인 2단계 이상이면 '승인 병목' +2.5 등). '한 번 더 도전하기'를 누르면 순위 기반 조합이 겹치지 않게 순환합니다.

**가장 효과적인 선택**: 각 선택을 하나씩 뺐을 때와 결과를 비교합니다. 노동·대기·품질·위험 차이에 성공 기준(Q.E) 가중치를 곱해 순위를 매깁니다.

## 5. 수정하기 쉬운 기본값 (`src/engine/config.ts`)

| 설정 | 내용 |
|---|---|
| `TYPE_PROFILE` | 업무 유형별 자동화 상한, 검토 비중, 대기 비율, 검토 비율, 승인자 부담, 추천 적용 가능성, 기존·AI 프로세스 단계 이름 |
| `LEVEL_PROFILE` | AI 활용 0~4단계별 이미 실현한 비율, 현재 AI 사용 비율, 오류율, 유지관리 시간, 지시 비율 |
| `APPLICABILITY_MULT` | 적용 가능성 배수 |
| `SIM` | 공통 상수 (대체율 상한, 재작업 비용, 검토 적발률, 요청 증가, 품질·위험 계수 등) |
| `REDESIGN` | STEP 4 재설계 토글 4개와 효과 |
| `EVENTS` | (상황 대응 단계는 삭제됨 · 데이터만 남아 있음) |
| `EVENT_AFFINITY` | 상황 카드 개인화 규칙 |
| `ENV` | 일하는 환경 설문(Q.G·Q.H) 선택지와 계산 배수 |
| `CRITERIA_WEIGHTS` | 성공 기준별 '가장 효과적인 선택' 가중치 |
| `EDU_EXAMPLES` | 교육기획 예시 업무 |
| `REINVEST` | 확보 시간 재투자 항목 |
| `HOUR_BASES` | 실행 인사이트 근무시간 빠른 선택·비교 값 (기본 40·52시간) |
| `ARCHETYPES` | 네 유형의 이름·아이콘·설명 |
| `LABELS` | 화면의 모든 선택지 문구 |

모든 결과는 가정에 기반한 교육용 추정치입니다. 소모임에서는 "왜 이 숫자가 나왔는지"를 '계산 근거 보기'로 함께 확인하며 토론하는 용도로 쓰는 것을 권장합니다.
